# omp-settings-zh 产品需求文档

- 状态：已定义，待实现
- 基线版本：OMP 18.0.4
- 文档日期：2026-08-25

## 1. 背景

OMP 的 `/settings` 面板由统一设置 Schema 驱动，包含大量影响模型、上下文、工具、任务、安全和界面的选项。中文用户能够操作英文界面，但理解成本高，尤其容易忽略说明文本中的副作用、风险警告和生效条件。

维护完整中文分支会复制上游功能代码和发布责任。当前已发现的第三方中文分支基于 OMP 17.2.x，而官方版本已进入 18.0.x，说明完整分支存在明显更新滞后风险。

本项目只解决一个问题：**在不脱离官方 OMP 的前提下，让原生 `/settings` 面板的设置文案显示为简体中文。**

## 2. 目标用户

主要用户：

- 使用官方 OMP 的简体中文开发者；
- 能理解命令、配置键和技术专有名词，但希望降低设置说明阅读成本；
- 希望及时获得 OMP 官方更新，不愿切换到第三方完整分支。

次要用户：

- 希望贡献中文翻译或维护术语一致性的社区成员；
- 希望参考本项目为其他语言制作设置翻译包的 OMP 用户。

## 3. 产品目标

### G1：降低设置理解成本

用户打开原生 `/settings` 后，设置名称、说明、分组、风险警告和有限选项应优先显示简体中文。

### G2：不影响官方更新

插件不得复制、代理或替换 OMP 业务逻辑。用户继续安装和运行官方 OMP。

### G3：兼容性可见

每个 OMP 版本下的翻译覆盖率和兼容状态应可检测。新增设置不得因为没有翻译而消失。

### G4：可社区维护

翻译数据、术语规范、检查脚本和贡献流程应公开、可审查、可自动验证。

## 4. 非目标

首个版本不承担：

- OMP 全局 TUI 汉化；
- CLI `--help` 和错误消息汉化；
- 系统提示词、工具描述、Agent 角色或文档汉化；
- 中文命令别名；
- 模型输出语言控制；
- 配置值、路径、环境变量或程序标识符翻译；
- 在线机器翻译；
- OMP 分支、二进制重打包或自动补丁。

## 5. 核心用户流程

### 5.1 安装

1. 用户使用 OMP 原生 `plugin install` 或 `plugin link` 安装插件。
2. OMP 验证插件入口并记录启用状态。
3. 下一次启动会话时插件自动加载。

### 5.2 查看和修改设置

1. 用户照常输入 `/settings`。
2. OMP 打开官方设置面板。
3. 插件已在面板构建前覆盖显示元数据。
4. 用户看到中文页签、分组、设置名称、说明和选项说明。
5. 用户通过官方控件修改设置。
6. OMP 使用原有逻辑验证并保存配置。

### 5.3 遇到上游新增设置

1. 插件识别到官方 Schema 中存在未收录路径。
2. 未收录设置保留官方英文文案。
3. 已收录设置继续显示中文。
4. 兼容报告列出未翻译路径，供维护者补充。

### 5.4 遇到不兼容版本

1. 插件启动时检测所需导出、对象结构和可写性。
2. 任一关键前置条件不满足时，插件不应用任何翻译。
3. OMP 继续以官方英文界面运行。
4. 用户收到一次明确、可操作的兼容性提示。

## 6. 功能需求

### FR-01：原生设置面板复用

插件必须继续使用内置 `/settings` 命令及官方 `SettingsSelectorComponent`，不得注册同名命令或复制一套设置编辑器。

### FR-02：设置文案覆盖

插件必须能够按稳定的设置路径覆盖以下字段：

- `ui.label`
- `ui.description`
- `ui.warning`
- `ui.group`
- `ui.options[].label`
- `ui.options[].description`

翻译记录不得修改选项的 `value`。

### FR-03：页签和分组覆盖

插件必须翻译 `TAB_METADATA` 的显示名称，并同步翻译设置项所属分组与 `TAB_GROUPS` 的排序列表。

### FR-04：英文回退

翻译表中不存在的页签、分组、设置项或选项必须保留官方原文。缺失翻译不得抛出异常、隐藏设置或改变排序。

### FR-05：兼容性预检

应用翻译前必须一次性验证：

- 所需模块可以解析；
- 所需导出存在；
- Schema 和元数据结构符合预期；
- 待修改对象和属性可写；
- 翻译中的设置路径和选项值可以与当前 Schema 匹配。

关键检查失败时必须整体停止应用，避免部分中文、部分损坏的状态。

### FR-06：幂等性

同一进程内重复加载或重新执行应用函数，不得重复拼接文字、改变排序或产生不同结果。

### FR-07：覆盖率报告

项目必须提供开发期检查命令，输出至少包括：

- 当前含 UI 元数据的设置总数；
- 已翻译设置数；
- 完整翻译数；
- 部分翻译数；
- 未翻译设置路径；
- 翻译表中已被上游删除的路径；
- 选项值不匹配项。

运行时默认不打扰用户；仅在不兼容或翻译应用失败时通知。

### FR-08：无运行时网络请求

插件运行时不得访问网络、调用 LLM 或发送遥测。所有翻译必须随插件发布。

### FR-09：保留敏感设置语义

插件不得读取、记录或展示被标记为凭据或秘密的当前值。翻译层只接触 Schema 元数据。

### FR-10：可卸载

通过 OMP 原生插件管理卸载或禁用后，下一次进程启动必须恢复完整官方英文界面，不修改用户配置文件。

## 7. 翻译范围和优先级

P0：

- 所有设置页签；
- 所有设置分组；
- 所有具有 UI 元数据的设置名称与说明；
- 所有风险警告；
- 所有静态选项名称与说明。

P1：

- 设置面板中由官方源码硬编码、但不属于 Schema 的搜索提示和按键提示；仅在上游提供稳定本地化接口后实施。

明确不翻译：

- 主题名、模型名、提供商名；
- 命令名和配置键；
- 路径、URL、环境变量；
- 工具名、协议名、代码标识符；
- 作为程序逻辑值使用的字符串。

## 8. 质量要求

### QR-01：行为零变化

启用前后，除显示文本外，设置路径、当前值、可选值、默认值、条件显示、排序和保存结果必须一致。

### QR-02：启动安全

插件加载失败不得阻止 OMP 启动。兼容失败必须失败关闭并保留英文。

### QR-03：性能

翻译覆盖只在插件初始化时执行一次，复杂度应与 Schema 条目数线性相关；不得在每次渲染时查表或分配完整副本。

### QR-04：可维护性

业务逻辑、OMP 适配层、翻译数据和验证脚本必须分离。翻译贡献不应要求理解 TUI 实现。

### QR-05：可审查性

翻译数据必须是确定性的文本文件。自动生成内容必须可重建，并在提交中保留来源说明。

## 9. 验收标准

首个可发布版本必须同时满足：

1. 使用官方 OMP 基线版本启动成功。
2. 输入 `/settings` 后仍打开官方设置面板，而非插件自建面板。
3. P0 范围内翻译覆盖率达到 100%。
4. 修改布尔、枚举、数字、文本、多选和凭据类设置的行为与未安装插件时一致。
5. 搜索既能命中中文设置名称，也不破坏官方设置路径和英文回退项。
6. 模拟新增设置时，该项显示英文且其余翻译正常。
7. 模拟删除设置和选项变化时，检查命令准确报告漂移。
8. 模拟关键导出缺失或对象冻结时，插件不应用任何翻译，OMP 保持可用。
9. 插件运行期间无网络请求，无配置值采集。
10. `omp plugin link`、禁用和卸载路径均经过真实 OMP 验证。

## 10. 发布边界

### 0.1.0

- 完成 P0 翻译；
- 支持 OMP 18.0.4；
- 支持本地链接和 GitHub 安装；
- 提供覆盖检查、单元测试和真实 TUI 冒烟验证。

### 后续版本

- 跟随上游 Schema 变化补充翻译；
- 推动 OMP 提供正式设置本地化注册 API；
- 官方 API 可用后移除内部对象修改；
- 在不扩大核心边界的前提下评估其他语言包。

## 11. 成功指标

项目不内置遥测。通过以下公开、非侵入指标判断：

- 发布版本对目标 OMP 版本的 P0 翻译覆盖率；
- 上游发布后兼容检查恢复通过所需时间；
- 与误译、设置行为变化或兼容失败相关的 Issue 数量；
- 社区翻译贡献的合并效率。
